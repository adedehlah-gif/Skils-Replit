# Replit Project Rules — UI/UX First

These rules complement `.agents/skills/pro-ui-ux/SKILL.md`.

## Mandatory instruction
For every task that creates, modifies, reviews, or fixes a user-facing interface, read and follow `.agents/skills/pro-ui-ux/SKILL.md` **before editing code**. This includes new projects, redesigns, pages, components, dashboards, forms, responsive fixes, and visual bug fixes. Re-read it when beginning a new UI task if its requirements are not in the current context.

## Project-start checklist
1. Inspect the existing repository and identify its framework, routes, styling system, assets, and scripts.
2. Read the UI/UX skill.
3. Preserve the existing architecture and behavior unless the user explicitly requests a change.
4. Plan a consistent design system and responsive layout before implementation.
5. Implement working controls, accessible states, and real data integration where available.
6. Run available checks and inspect the preview when possible.
7. Report what changed and which checks were actually run.

## Priority
User requirements and safety constraints take priority. Follow the existing product brand where one exists; use the skill's reference-inspired palette and dashboard composition as guidance, not as a mandatory template for every screen.

Do not claim the skill is automatically enforced in every Replit project merely because this file exists. Install it at the workspace/account level where supported, or include these rules and the skill in each project that should use them.
